## Time: exact current work and safe first changes

Source: [time-panel.js](../web/js/scales/scale0/ui/overlays/time-panel.js), [time-analysis.js](../web/js/scales/scale0/analysis/time-analysis.js), [retained-readout.js](../web/js/ui/panels/retained-readout.js), and [Scale-0 capabilities](../web/js/bridge/capabilities/scale0.js).

### Current observation and rendering path

1. `update` runs at 2 Hz after first visible activation (`time-panel.js:43,569–715`). It resets twin integration on owner identity, hub reset version or a known source-boundary change. Hidden callbacks release this panel's sampler wants, clear the quadrature time latch and return before sampling. The existing hidden callback itself is lightweight and remains registered after initial activation.
2. Every valid visible update requests `latency@max(2,ceil(L/25))`, `tau@1`, `lapse@1`, `dbPhase@1` (`594–596`). It reads a separate `getScale0GravityMetricAgg` record (`628`), then the latency sample (`477–484`), a centre-voxel inspection and scalar clock/toggle values (`665–690`), and three proper-time samples (`495–544`). Requested stride and actual emitted support are distinct: the native visual grid can raise effective stride. Do not alter either to meet a timing gate.
3. Direct latency sampling first scans all lattice flux components for its native normalization, then visits the regular sample grid (`ftd_wasm.cpp:1239–1258`). The separate native gravity aggregate also scans the voxel domain on the host path (`render_bridge.cpp:484–517`). Its data is the Poisson-derived engine latency map, distinct from the normalized flux proxy; the two cannot be substituted for one another.
4. The three direct proper-time samplers independently visit the same requested regular grid and select manifested sites. They emit Float32 values and positions through `sample_scalar_overlay` (`ftd_wasm.cpp:599–628,1347–1388`). Their static vectors already retain capacity. Do not apply the separate flux-vector whole-record-reset diagnosis to these scalar buffers. At direct L33/stride1 each of the three loops visits 35,937 grid sites before manifestation filtering; emitted counts can be much smaller.
5. Worker getters read cached owned sampler records, not synchronous native scans on the main thread (`wasm-bridge-proxy.js:982–1054`). Worker scheduling places Time/Gravity instrument demands in a bounded 4 Hz batch and injects `gravityMetricAgg@0` for Time-only demand (`wasm-bridge.worker.js:657–680`). The Time callback remains 2 Hz. Different delivery, producer, panel and rendering cadences must not be relabelled as one clock.
6. `radialSummary` performs one pass when the panel supplies its known geometric maximum radius. It allocates 12-bin Float64 sums, Uint32 counts and occupied-bin records (`time-analysis.js:61–98`). It consumes the minimum of the values length and the complete position-triple count, rather than the sampler's `count` property. It uses strict `L > lDeep` to retain the first equal maximum's radius. It keeps emitted positions, including their existing half-cell offsets. A cache keyed only by L/stride would be insufficient because amplitude filtering can change which positions are present.
7. Card B builds up to 12 measured points, 25 reference points and several temporary arrays; evaluates its residual over occupied bins; then emits complete SVG/string markup (`time-panel.js:181–228`). The active expression is `clockRate(lMax * min(1, r0/max(r0,r)))`. Preserve this exact expression, 25-point support, clamping, r0 fallback, axes, precision and residual denominator. Do not replace it using an older explanatory comment's different radial formula.
8. Cards A/B/C/E/F assemble complete strings before `updateRetainedReadout` sees them. The helper skips byte-identical markup, but changed markup still creates a detached template subtree and traverses its attributes/text before updating the retained live tree (`retained-readout.js:8–58`). Stable live nodes do not eliminate parsing, intermediate strings or reconciliation work. Card C copies only its visible history window; v2 already removed copies of hidden history. Card D already redraws only when imposed velocity changes and owns its form control separately (`427–469`). It is not a recurrent 2 Hz curve-rebuild target.

### T1: dedicated retained value and SVG slots

Implement first as a JavaScript-only candidate inside Time's own renderer module. Build each stable card structure once, retain direct references to numeric text nodes, dynamic explanatory text, styles, SVG paths/dots/grid labels and optional sections, and update only changed properties. Keep the actual formulas and formatting functions unchanged. Retain or explicitly transition among unavailable, no field, sparse field, inactive/active clock and optional aggregate states.

For Card B, generate the same numerical chart geometry and set the same SVG attributes directly; reuse existing circle/path elements when their structural roles persist. For Card C, compute the same visible-window path and keep the same complete underlying histories. Cards E/F require dynamic titles as well as numeric text. Use the established tooltip channel correctly when the global tooltip manager has moved a native `title` into `data-ui-tooltip`; repeated tooltip reintroduction and stripping is not required scientific work. Test both before and after that migration.

Card F's enable button is an interaction surface. Keep its real checkbox `change` dispatch and qualification/mutation plumbing. Its existing delegated listener must survive state transitions. Do not put Card D's range input into the generic retained helper or remove its input-triggered chart refresh. Changes in scientific status must remain visibly represented even when the numeric strings happen to be equal.

Keep sampler calls, demand cadence, qualified diagnostics checks, centre inspection, aggregate read, published proper-time metrics and integration order unchanged in T1. This narrows the equivalence proof to presentation. It does not claim the presentation work is the dominant deficit or that T1 alone will pass.

### T2: reduction changes only after attribution

If T1 is insufficient, use measured nested stage timing to select a second independently reviewed change. A shared native traversal for tau/lapse/phase can preserve emitted values only with an explicit contract: identical regular support and order, the same manifestation predicate, separate Float32 rounding before JavaScript reductions, all returned per-kind counts/origins/effective strides, exact zero-rate samples, and unchanged asynchronous publication qualification. Each JavaScript sum must retain its original input sequence and expression order. A direct Float64 aggregate or a C++ replacement of JavaScript phase trigonometry is not automatically equivalent.

Such native batching is a larger interface change requiring fresh C++/WASM artifacts and parity checks; it is not authorized merely by this document. A cached engine aggregate keyed only by tick is unsafe because same-tick mutations exist. Reusing the hub's different or stale aggregate changes the observation. Likewise do not cache a radial profile by tick or assume a sparse positions array is immutable across native calls. Observe the binding's synchronous view lifetime and avoid retaining a view across a call that may invalidate it.

The radial calculation is already one pass with only 12 bins. Do not introduce a geometric lookup cache until its cost matters and its key validates actual support coordinates, centre, maxRadius and bin count. Retain the first-maximum tie, emitted half-cell positions and accumulation order.

## Gravity: exact slice contract and staged optimization

Source: [gravity-panel.js](../web/js/scales/scale0/ui/overlays/gravity-panel.js), [gravity-analysis.js](../web/js/scales/scale0/analysis/gravity-analysis.js), [slice-render.js](../web/js/scales/scale0/ui/overlays/slice-render.js), [worker proxy](../web/js/bridge/wasm-bridge-proxy.js) and [pinned publication](../web/js/bridge/flux-publication.classic.js).

### Current work and why a plain slice getter is insufficient

`gravity-panel.js:647–804` gates scientific work on scenario applicability, exact authoritative load readiness and visibility. It owns 4 Hz sampler demands, with stride 2 at L33 and 6 at L97. An accepted live update reduces latency, curvature and force samples, obtains the separate gravity aggregate, paints one rotating plane, updates retained telemetry and traces, and appends history only when the accepted `fieldDataVersion` changes. Stable paused direct-WASM data avoids volume work. Asynchronous replies can advance while that version is fixed; the code keeps polling and only accepts subsequent comparable sample vectors when every component's version advances.

For the worker path, `paintSlices` obtains `getScale0FluxVolume`, scans its full magnitude array with `maxRhoOf`, then computes one plane (`598–640`). The proxy's volume getter uses a pinned full Float64 copy on a new publication (`wasm-bridge-proxy.js:884–906`, `flux-publication.classic.js:64–74`). At L97 that snapshot is **912,673 Float64 entries / 7,301,384 bytes** before the max scan. Reusing an unchanged cached publication avoids that copy; it is not correct to claim every getter necessarily allocates. The visible hardware rows recorded volume-getter p95 1.485 ms docked and 1.940 ms floated, but those whole-page rows are not paired stage samples.

`maxRhoOf` initializes `mx=1e-30` and applies `r=mag[i]*mag[i]; if (r>mx) mx=r` over the entire volume. All latency, dilation and curvature planes use that global normalizer. A plane-only maximum changes the observable whenever the peak lies elsewhere. A diagnostics maximum is neither guaranteed to have the same arithmetic nor the same publication. Both substitutions are rejected.

The current slice creates an N² Float64 raw array, a second N² Float64 transpose/flip array, scans the final plane for its color normalization, then paints it. At L97 the two arrays total 150,544 bytes. Canvas ImageData, byte storage and the temporary canvas are already reused per N (`slice-render.js:95–118`); an alleged new ImageData allocation on every call would be incorrect. Telemetry and delta rows already retain DOM references. The remaining tile `textContent` assignment can replace a text node even with a stable tree, but is a small candidate rather than proof of the callback deficit.

### G1: exact synchronous slab observation, retaining the global scan

Preferred first worker-read candidate: add an explicitly named observation accessor for an owned three-plane magnitude slab and its **same-publication full-volume maximum**. Implement it only after the frozen campaign closes and shared interface ownership is assigned.

The accessor must acquire one existing pinned publication, scan that pinned volume with the exact `maxRhoOf` arithmetic/order, and copy the central plane plus its immediate normal neighbors before releasing the pin in `finally`. All same-plane face/edge neighbors are then present in these full planes. For an interior L97 plane the slab contains 3 × 97² Float64 entries, **225,816 bytes**, rather than a 7,301,384-byte dense copy. Near a domain edge, the contract must explicitly represent the valid planes and existing zero-border behavior. No padded invented periodic values are allowed: this display stencil currently zeros border outputs.

This removes the dense snapshot allocation/copy on this path. It **does not eliminate** the O(N³) normalization scan, the stencil arithmetic, painting or scalar metric reductions. The scan remains inside the panel's inclusive callback. This synchronous version adds no asynchronous observation interval; its publication selection remains a single acquisition. It can hold the visual read pin longer than a pure plane copy, so producer contention and successful visual-publication rate require measurement. An unavailable acquisition returns explicit unavailable data under a frozen fallback contract, never a partly read slab, mixed publication or newly synthesized zero plane. Existing completed all-zero fields remain valid observations.

Keep the existing ownership fences: readiness/disposal, owner identity, pending/applied configuration equality, buffer identity and generation, dimensions, selector validity, and before/after checks. Return owned arrays with immutable metadata containing publication version, buffer generation, configuration token, lattice size, slab support and representation. **`sampleTick` remains null** unless a new exact clock-binding protocol is separately proved; the signed publication version is not a physics tick or global lineage ID. Check every exception/early return releases the pin. Preserve existing slice/cell/full-volume public APIs for their other callers.

For lower risk, keep existing proxy formulas in the analysis module and provide a slab-aware accessor to the same logical coordinates. Preserve each operation order in `gravitySlice:168–216`: all six face and twelve edge contributions, face/edge coefficients, `-4*self`, spacing powers, clamp and squaring; radius-one display force remains distinct from the separately sampled radius-two engine force. Preserve output indexing `raw[a*N+b]`, the transpose/flip `out[(N-1-b)*N+a]`, strict maximum comparisons, thresholds, ramp lookup, byte conversion and nearest-neighbor canvas scaling. `latency`, `dilation`, `kretschmann` and `force` all need equivalence tests.

Do not change the direct-WASM or compact native FTV2 path as a side effect of G1. The direct path deliberately performs all later WASM calls before obtaining and synchronously consuming its zero-copy volume (`gravity-panel.js:745–752`). The compact path retains its physical stride/origin, exact middle-plane resolution and proxy disclosures. These paths already have specific regressions in [the Gravity overlay audit](../web/tests/scale0-gravity-overlay-audit.spec.js).

### G2: reuse local buffers and reductions

After G1 attribution, a panel-owned scratch buffer can avoid repeated raw/transposed allocations, or a slab renderer can write to the final flipped index directly. This is safe only for buffers consumed synchronously and never returned as immutable observations or retained by unrelated callers. Dimension, quantity and owner changes must reset the appropriate cache. Compare raw/final arrays and rendered pixels before choosing either approach.

`aggregateMetrics` currently calls `metricStats` and `histogram` separately for each scalar (`gravity-analysis.js:224–239`). Histogram repeats a range scan already performed by metricStats, then bins values; force magnitude construction adds another array/pass. A local combined stats/range helper can remove a duplicate scan while retaining every per-series addition order, RMS calculation, empty/default behavior, nonfinite behavior, 22-bin rules, `max==min` adjustment and strict comparisons. A two-pass exact histogram still needs its range before binning. This is a bounded optional improvement, not justification to change the shared topology functions for every consumer or to presume the scalar reductions dominate.

A retained text-node setter for slice captions can remove equal-value `textContent` replacement. Existing Gravity `setText`/`setAttr` helpers and retained telemetry/delta views already avoid much of this work. Preserve force-branch labels, counterfactual/off status, requested-but-zero aggregate status, asynchronous revision descriptions and all histogram/sparkline values. Removing labels, curves or precision is not a performance repair.

### G3: asynchronous worker computation is a separately priced fallback

If the remaining full-volume scan still fails the callback gate, moving that work to a worker requires a new observation contract. Exact values for a given publication can be preserved, but the display acquires additional queue/compute/publication latency. This cannot be described as unchanged observation timing.

Both slab values and the global maximum must derive from **one pinned publication** or an immutable copy of that publication. Computing a max during a different native/worker frame and attaching it to the latest plane is forbidden. Adding a per-slot max to the existing publication format requires a versioned layout with the scalar written under the same slot lock before publication; it also adds producer work. A separate analysis worker must not become an unregistered second reader of the current single-reader protocol. Declare reader ownership and arbitration explicitly rather than assume that sharing a buffer provides a safe lease.

Requests/results must bind owner, scenario/load intent, configuration, buffer generation, publication, support, quantity and a monotonic request identity. Use bounded in-flight work and completed mailboxes. Hide/collapse, new load, owner replacement, quantity change and disposal must invalidate stale responses. Record cancelled/dropped optional observations, source acquisition and completion/publication times, and the actual age of visible results. Keep the sample tick unknown when only a buffer version is known. Physics transactions may never be dropped to improve rendering.

The registered 4 Hz callback must still include result validation and presentation. Measure capture, compute, worker load and publish timing rather than remove cost from instrumentation. Delayed visual results cannot silently delay or change accepted telemetry history. Preserve separate provenance for the independent scalar samplers and proxy plane; simultaneous completion does not prove same-tick fields. A preregistered bounded end-to-end age gate and all three-plane quantity-action response checks are required before this option is eligible. No acceptable numerical age bound is chosen in this document.

### Gravity correctness regressions required

- Compare complete results to the frozen dense path for all four quantities, all axes and supported slab positions, using manufactured asymmetric fields. Put the global extremum off all displayed mid-planes and outside the retained slab to catch incorrect local normalization. Cover all-zero, signed manufactured magnitudes where the old arithmetic permits them, very small values, clamp crossings, nonfinite inputs and tiny/edge domains; preserve the old domain or explicitly classify any changed invalid-input handling as a separate correctness change.
- Use fixtures with nonzero individual face/edge neighbors to pin the 18-neighbor curvature expression, radius-one display-force stencil, border zeros, half-cell/support conventions, stride/origin and output orientation. Compare exact Float64 arrays in the same JavaScript engine, then all RGBA bytes and canvas orientation. Do not use image similarity alone as the numerical oracle.
- Test publish/acquire contention, cached-publication behavior, publication-counter wrap, constructor/copy exceptions, source-buffer rebind, configuration mismatch, owner/disposal changes during reading and post-read validation. No torn output, leaked pin or mutation of returned observations is acceptable. Do not rely on a fixed atomic tick to identify the sampled plane.
- Preserve stable paused direct behavior, paused asynchronous replies that advance at unchanged field version, delayed individual sampler components, completed zero-count samples versus absent caches, and required advancement of every comparable sampler version. Do not replace `samplerVersionsAdvanced` with an any-component rule or claim transport revisions are common physics time.
- Preserve history append-on-new-accepted-field-version, previous accepted observation as delta baseline, inclusive history windows and full `All` history. Refresh one rotating plane per scheduled callback, three immediately on a quantity action. A render cache must include active quantity, publication, support and normalization and must not suppress completion of the other planes or a user's quantity change.
- Rerun actual mounted applicability/load/empty/owner/visibility/disposal tests and real branch/toggle-label tests. Hidden/collapsed and empty/pending states remain inert for sampling and canvas work. Keep the direct zero-copy consumption order and native compact-grid origin test unchanged unless their own contract is deliberately amended and independently reviewed.

## Implementation ownership, evidence and exit

The coordinator should freeze T1 and G1 interfaces before assigning work. A Time implementer owns the Time renderer and its focused tests. A separate worker-read implementer owns the publication/proxy accessor, Gravity integration and its focused tests; the coordinator arbitrates shared capability and harness changes. Any native batching needs a separately assigned native owner and a fresh artifact wave. Implementers are not their own auditors.

Attribution should be a bounded opt-in test probe covering actual capability/`getSamplerOr` calls, the native aggregate, reduction, markup/slot updates, slab capture, normalization, proxy computation and paint. Keep one root timing per existing scheduled callback and correlated nested sample identities; do not add nested diagnostic timings as independent failing panel callbacks, subtract quantiles or move scientific work to unmeasured rAF tasks. Probe storage and overhead must be bounded and separately disclosed. Preserve the original uninstrumented workload comparison where nested probes materially change cost.

After actual-source correctness tests and independent review, freeze a distinct candidate revision, complete source/artifact manifest and archive. Run the registered panel and affected-overlay matrix serially on foreground hardware ANGLE/RTX 5090, with the same preparations, backend sizes, visibility states, ten action samples, >=600 frame intervals and >=12-second durations. Preserve p95/max callback, whole-frame, long-task, lifecycle, ownership, qualification and hidden-work gates. If the shared publication or helper changes affect other consumers, broaden the matrix to those actual consumers; existing passes do not exempt modified paths.

Acceptance requires every affected mandatory gate to pass and every value/provenance difference to be explained. Improvements remain unmeasured until that new campaign. The current aggregate timings cannot determine whether Time T1 or Gravity G1 will suffice, whether worker copy or max scan dominates a particular outlier, or how `All` history scales during a much longer session. The finite measured workload does not establish a universal always-60-FPS guarantee. Strict microscopic dynamics, continuum closure, restoring matter and higher-scale recovery retain their separate research gates.
