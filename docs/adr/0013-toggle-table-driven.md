# 0013 — Toggle table-driven design (TOGGLE_SPECS[])

**Status:** Accepted
**Date:** 2026-04-27
**Author:** refactor sweep Phase 6 (commit 2aa2df9)

## Context

Pre-Phase-6, adding a new bool toggle to `TermToggles` required FIVE
edits in lockstep: (1) the struct field declaration, (2) a `validate()`
if-chain entry for any dependency check, (3) `enable_all()` body line,
(4) `disable_all()` body line, (5) `rb_toggle_map` entry in
`engine/wasm/bindings_render_bridge.cpp`. The 4-place-edit drift hazard
was documented in the pre-refactor audit (Track F refactor backlog,
RF-9). Multiple recent toggles had landed with one or more of the five
sites missing — silently disabling the toggle or producing console
noise from the validator.

## Decision

Replace the hand-written helper methods with a `static constexpr
TOGGLE_SPECS[]` table that the helpers iterate:

```cpp
struct ToggleSpec {
    const char* name;
    bool TermToggles::*field;       // typed pointer-to-member
    bool default_value;
    bool bulk_managed;              // skip in enable_all/disable_all if false
    const char* requires_;          // empty or comma-separated names
    const char* conflicts;          // empty or single name
    const char* gpu_only_warning;   // text or empty
    ToggleBackend backends;         // bitmask CPU=1, GPU=2, JS=4
    const char* description;
};

inline constexpr ToggleSpec TOGGLE_SPECS[] = {
    {"wave_propagation", &TermToggles::wave_propagation, true, true, "", "", "",
     ToggleBackend::ANY, "Phase-read 18-pt Laplacian"},
    {"weak_transmutation", &TermToggles::weak_transmutation, false, true,
     "dual_substrate", "larmor_radiation", "", ToggleBackend::CPU_GPU,
     "Flavor-changing weak"},
    // ... 23 more rows ...
};
```

`validate()`, `enable_all()`, `disable_all()`, `cpu_runtime_warnings()`,
and the WASM `rb_toggle_map()` are all auto-generated by iterating
`TOGGLE_SPECS`. Adding a new toggle is now a 2-place edit: the field
declaration (unavoidable — actual storage) plus one table row.

## Consequences

- (+) New toggle = 2-place edit (5→2 collapse on metadata sites)
- (+) Single source of truth for toggle metadata
- (+) Self-documenting: every toggle has `description` for tooltips/UI
- (+) Backend filter (`backends` bitmask) lets the WASM map filter by
  `ToggleBackend::JS` cleanly
- (−) Slightly more verbose per-row than a hand-rolled bool field
  (one row vs one line)
- (−) Compile-time NVCC dependency tracking didn't pick up `term_toggles.h`
  changes for the CUDA library on the first build, requiring a manual
  `engine/build/cuda/` clean — documented as an ABI hazard for future
  edits

## Alternatives considered

- X-macro (preprocessor) — rejected: opaque to debuggers and to LLM
  agents reading the source
- Code-generated C++ from a JSON schema — rejected: build-pipeline
  complexity not warranted for 25 toggles
- Status quo (5-place edit) — rejected: drift hazard already manifesting
